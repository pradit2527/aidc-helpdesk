# AIDC Support Kit

ปุ่มแชทของ Helpdesk สำหรับเว็บทุกตัวในเครือ AIDC

ผู้ใช้เว็บของคุณกดปุ่มมุมจอแล้วพิมพ์ถามได้ทันที ข้อความไปโผล่ในกล่องแชทเดียวกับที่ทีมไอที
ใช้อยู่ทุกวัน ติดป้ายชื่อโครงการของคุณไว้ เจ้าหน้าที่ตอบกลับจากที่นั่นที่เดียว

สิ่งที่ทีมคุณต้องรู้มีอย่างเดียวคือ **รหัสโครงการ** ที่ผู้ดูแล Helpdesk ตั้งให้
ไม่ต้องรู้ว่าเบื้องหลังใช้อะไร ไม่ต้องขอ token ไม่ต้องตั้งค่าอะไรเพิ่ม

---

## 1. ติดตั้ง

วางบรรทัดนี้ก่อนปิด `</body>` ของทุกหน้า แล้วจบ

```html
<script src="https://helpdesk.aidclaos.com/kit/v1/aidc-support.js" data-project="ILP" defer></script>
```

เปลี่ยน `ILP` เป็นรหัสโครงการของคุณ (ขอจากผู้ดูแล Helpdesk — ดูข้อ 5)

ตัวเลือกเพิ่มเติมบนแท็กเดียวกัน

| แอตทริบิวต์     | ค่า                 | ค่าเริ่มต้น              | ใช้ทำอะไร                        |
| --------------- | ------------------- | ------------------------ | -------------------------------- |
| `data-project`  | รหัสโครงการ         | **จำเป็น**               | บอกว่าแชทนี้เป็นของเว็บไหน       |
| `data-locale`   | `lo` \| `th` \| `en` | ค่าที่ตั้งไว้ในโครงการ   | ภาษาของปุ่มและข้อความในหน้าต่างแชท |
| `data-position` | `right` \| `left`   | `right`                  | ปุ่มอยู่มุมขวาหรือมุมซ้าย         |

> สคริปต์อ่านที่อยู่ของ Helpdesk จาก `src` ของตัวเอง — ถ้าคุณชี้ไป staging
> มันจะคุยกับ staging ให้เองโดยไม่ต้องแก้อะไรเพิ่ม

## 2. เว็บที่มีการเข้าสู่ระบบ: บอกว่าใครกำลังคุยอยู่

ถ้าไม่บอก เจ้าหน้าที่จะเห็นแค่ "ผู้เข้าชมเว็บ" แล้วต้องเสียเวลาถามชื่อ ถามบริษัท
ถามอีเมลใหม่ทุกครั้ง เรียกหลังผู้ใช้ล็อกอินสำเร็จ

```js
AIDCSupport.identify({
  identifier: user.id,        // จำเป็น — ค่าที่ไม่ซ้ำและไม่เปลี่ยน เช่น id ในฐานข้อมูล
  name: user.fullName,
  email: user.email,
  phone: user.phone,
  company: user.companyName,
  hash: identityHash,         // มาจากเซิร์ฟเวอร์ของคุณ ดูข้อ 3
});
```

เรียกได้ทันทีโดยไม่ต้องรอ — คำสั่งที่มาก่อนวิดเจ็ตพร้อมจะถูกเก็บคิวไว้แล้วเล่นให้เอง

**ตอนผู้ใช้ออกจากระบบต้องเรียก `reset()` เสมอ**

```js
AIDCSupport.reset();
```

ถ้าไม่เรียก คนถัดไปที่ใช้คอมพิวเตอร์เครื่องเดียวกัน (ซึ่งเกิดขึ้นจริงทุกวันที่สาขา)
จะเปิดแชทแล้วเห็นบทสนทนาของคนก่อนหน้าทั้งหมด

### คำสั่งทั้งหมดของ `window.AIDCSupport`

| คำสั่ง                   | ทำอะไร                                                      |
| ------------------------ | ----------------------------------------------------------- |
| `identify(user)`         | บอกว่าใครล็อกอินอยู่ (ดูด้านบน)                              |
| `reset()`                | ล้างตัวตนและบทสนทนา — เรียกตอนออกจากระบบ                    |
| `open()`                 | เปิดหน้าต่างแชท เช่นจากปุ่ม "ติดต่อฝ่ายสนับสนุน" ของคุณเอง   |
| `close()`                | ปิดหน้าต่างแชท                                               |
| `toggle()`               | สลับเปิด/ปิด                                                 |
| `onReady(cb)`            | เรียก `cb` เมื่อวิดเจ็ตพร้อมจริง (ถ้าพร้อมอยู่แล้วเรียกทันที) |
| `version`                | เวอร์ชันของ kit อ่านได้อย่างเดียว                            |

ทุกคำสั่งปลอดภัยที่จะเรียกแม้วิดเจ็ตโหลดไม่สำเร็จ — จะไม่มี error หลุดออกไปหาเว็บของคุณ
ความผิดพลาดทุกชนิดจบที่ `console.warn` ข้อความเดียว

## 3. `hash` ต้องคำนวณที่เซิร์ฟเวอร์ของคุณเท่านั้น

`hash` คือลายเซ็นที่พิสูจน์ว่า "คนนี้คือคนนี้จริง" ถ้าไม่มี ใครก็เปิด console
แล้วพิมพ์ `AIDCSupport.identify({ identifier: 'ceo@...', name: 'ท่านผู้อำนวยการ' })`
เพื่อสวมรอยได้ทันที แล้วเจ้าหน้าที่จะเห็นชื่อผู้บริหารในกล่องแชทโดยไม่มีอะไรบอกว่าปลอม

หน้าจอของ Helpdesk แสดงให้เจ้าหน้าที่เห็นชัดว่าบทสนทนาไหน "ยืนยันตัวตนแล้ว"
และบทสนทนาไหนเป็นข้อมูลที่ผู้เข้าชมพิมพ์เอง — เว็บที่เซ็น hash มาจะได้ป้ายแรก

> ### กุญแจ HMAC ห้ามอยู่ในโค้ดฝั่งหน้าเว็บโดยเด็ดขาด
>
> ไม่ว่าจะใน JavaScript ในไฟล์ `.env` ที่ถูก bundle ไปกับหน้าเว็บ ใน HTML
> หรือส่งกลับมาทาง API ใดก็ตาม — กุญแจที่หลุดไปถึงเบราว์เซอร์เท่ากับไม่มีกุญแจ
> เพราะใครก็หยิบไปเซ็นเป็นใครก็ได้
>
> เก็บไว้ในตัวแปรสภาพแวดล้อมของเซิร์ฟเวอร์ชื่อ `SUPPORT_HMAC_KEY`
> และคำนวณ hash ตอนสร้างหน้าหรือผ่าน endpoint ของคุณเองเท่านั้น

วิธีคำนวณเหมือนกันทุกภาษา: `HMAC-SHA256` ของ **identifier** ด้วยกุญแจ แล้วแปลงเป็น hex

**Node.js**

```js
const crypto = require('crypto');

function identityHash(identifier) {
  return crypto
    .createHmac('sha256', process.env.SUPPORT_HMAC_KEY)
    .update(String(identifier))
    .digest('hex');
}
```

**PHP**

```php
function identity_hash(string $identifier): string
{
    return hash_hmac('sha256', $identifier, getenv('SUPPORT_HMAC_KEY'));
}
```

**C# (.NET)**

```csharp
using System.Security.Cryptography;
using System.Text;

static string IdentityHash(string identifier)
{
    var key = Environment.GetEnvironmentVariable("SUPPORT_HMAC_KEY")!;
    using var hmac = new HMACSHA256(Encoding.UTF8.GetBytes(key));
    var bytes = hmac.ComputeHash(Encoding.UTF8.GetBytes(identifier));
    return Convert.ToHexString(bytes).ToLowerInvariant();
}
```

ค่าที่ใช้เซ็นต้องเป็น `identifier` ตัวเดียวกับที่ส่งเข้า `identify()` เป๊ะ ๆ
ถ้าใช้ `user.id` เซ็น ก็ต้องส่ง `user.id` ไม่ใช่อีเมล — ไม่งั้นลายเซ็นไม่ตรงและถูกปฏิเสธ

## 4. แก้ปัญหา "ปุ่มแชทไม่ขึ้น"

เปิด console ของเบราว์เซอร์ก่อนเสมอ kit จะบอกสาเหตุไว้เป็นข้อความเดียวขึ้นต้นด้วย
`[aidc-support]` ถ้าไม่มีข้อความนั้นเลย แปลว่าไฟล์สคริปต์โหลดไม่ถึงตั้งแต่แรก

| อาการ                                             | สาเหตุที่พบบ่อยที่สุด                                                                                                    |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `ไม่รู้จักโครงการ "..."`                          | รหัสผิด หรือยังไม่ได้ลงทะเบียนโครงการ — ดูข้อ 5                                                                          |
| `ไม่รู้จักโครงการ` ทั้งที่แน่ใจว่าลงทะเบียนแล้ว   | โครงการถูกปิดใช้งานอยู่ — โครงการที่ปิดจะทำตัวเหมือนรหัสที่ไม่มีอยู่จริงทุกประการ ให้ผู้ดูแลเปิดใช้งานให้                 |
| `ยังไม่ได้เชื่อมกับ Chatwoot`                     | ลงทะเบียนโครงการแล้วแต่ยังไม่ได้ผูก inbox — ผู้ดูแล Helpdesk ทำให้ได้ในหนึ่งนาที                                        |
| `หน้านี้เป็น https แต่เซิร์ฟเวอร์แชทเป็น http`     | เบราว์เซอร์บล็อก mixed content ทิ้งเงียบ ๆ ต้องให้เซิร์ฟเวอร์แชทเป็น https                                               |
| `โหลดสคริปต์แชทจาก ... ไม่ได้`                     | ตัวบล็อกโฆษณา ไฟร์วอลล์ขององค์กร หรือ CSP ของเว็บคุณเอง — ดูตารางด้านล่าง                                                |
| `หน้านี้มีวิดเจ็ตแชทของตัวเองอยู่แล้ว`             | เว็บคุณติดตั้ง Chatwoot ไว้เองอยู่ก่อน kit จะไม่ทับของเดิม ให้เอาตัวเก่าออกก่อน                                          |
| `สคริปต์ถูกใส่ไว้มากกว่าหนึ่งครั้ง`                | แท็กซ้ำ เช่นอยู่ทั้งใน layout และในหน้า — เอาออกให้เหลืออันเดียว                                                          |
| ไม่มีข้อความอะไรเลยใน console                      | แท็ก `<script>` ไม่ได้ถูก render จริง หรือ path ผิด ลองเปิด URL ของไฟล์ตรง ๆ ดูว่าได้ JavaScript กลับมาไหม                |

### ถ้าเว็บของคุณตั้ง CSP ไว้

ต้องอนุญาตสองต้นทาง คือ Helpdesk (ที่มาของ kit และค่าตั้งต้น) และเซิร์ฟเวอร์แชท
แทนที่ค่าในวงเล็บมุมด้วยค่าจริงที่ผู้ดูแล Helpdesk ให้มา

```
script-src  <helpdesk-origin> <chatwoot-origin>
connect-src <helpdesk-origin> <chatwoot-origin> wss://<chatwoot-host>
frame-src   <chatwoot-origin>
img-src     <chatwoot-origin> data: blob:
media-src   <chatwoot-origin> blob:
font-src    <chatwoot-origin>
style-src   'unsafe-inline'
```

`connect-src` ต้องมี `wss://` ด้วย มิฉะนั้นแชทจะส่งได้แต่ข้อความตอบกลับไม่เด้งเอง
ผู้ใช้จะต้องกดรีเฟรชเองทุกครั้ง ซึ่งเป็นอาการที่หาสาเหตุยากที่สุดในรายการนี้

### ทดสอบโดยไม่ต้องแก้เว็บจริง

เปิด `https://<helpdesk-origin>/kit/demo.html` — เป็นหน้าเปล่า ๆ ที่ฝัง kit ไว้
พร้อมปุ่มเรียก `open()` / `identify()` / `reset()` และพิมพ์สถานะทุกอย่างลงบนหน้า
ให้เห็นโดยไม่ต้องเปิดเครื่องมือนักพัฒนา

> หน้านั้นต่อกับเซิร์ฟเวอร์แชทจริงที่ทีมใช้งานอยู่ — กดดูได้ แต่อย่าพิมพ์ข้อความส่งออกไป
> เพราะจะกลายเป็นบทสนทนาจริงที่เจ้าหน้าที่ต้องมานั่งปิดทีหลัง

## 5. ขอให้ผู้ดูแล Helpdesk ลงทะเบียนโครงการ

ส่งสี่อย่างนี้ไปให้ทีม Helpdesk

1. **ชื่อระบบ** ที่อยากให้เจ้าหน้าที่เห็นในกล่องแชท เช่น "ระบบ ILP"
2. **URL ของเว็บ** ที่จะฝังวิดเจ็ต
3. **บริษัทเจ้าของระบบ** (หรือบอกว่าเป็นระบบส่วนกลางที่ใช้ร่วมทั้งเครือ)
4. **เว็บนี้มีการเข้าสู่ระบบหรือไม่** — ถ้ามี ให้บอกด้วย เพราะต้องมีการส่งกุญแจ HMAC
   ให้ทีมคุณเพิ่มอีกขั้นหนึ่ง

ผู้ดูแลจะส่งกลับมาเป็นรหัสโครงการกับสคริปต์บรรทัดเดียวที่ก็อปไปวางได้เลย

## 6. สำหรับผู้ดูแล Helpdesk: เพิ่มเว็บใหม่เข้าระบบ

ทำตามลำดับนี้ ข้ามขั้นไหนไปจะได้อาการ "ปุ่มไม่ขึ้น" ที่หาสาเหตุยากกว่าที่ควร

1. **สร้าง inbox ใน Chatwoot**
   Settings › Inboxes › Add Inbox › Website ตั้งชื่อให้ตรงกับระบบที่จะรับซัพพอร์ต
   และใส่ URL ของเว็บนั้น

2. **ลงทะเบียนโครงการใน Helpdesk**
   ตั้งค่าระบบ › ໂຄງການທີ່ຮັບຊັບພອດ › ເພີ່ມໂຄງການ ตั้งรหัส (A–Z, 0–9, `_`)
   แล้วกด "ດຶງຈາກ Chatwoot" เลือก inbox ที่เพิ่งสร้าง ระบบจะเติมเลข inbox
   และ website token ให้เอง ตั้งหมวดหมู่ตั้งต้นและทีมที่รับผิดชอบด้วย

   > รหัสโครงการแก้ไม่ได้หลังสร้าง เพราะมันถูกฝังอยู่ในทุกหน้าของเว็บที่ติดตั้งไปแล้ว

3. **เว็บที่มีการเข้าสู่ระบบ: ส่งกุญแจ HMAC ให้ทีมนั้น**
   คัดลอกจาก Chatwoot › Settings › Inboxes › (inbox นั้น) › Configuration ›
   Identity validation แล้วส่งให้ **ทีมหลังบ้าน** ของเว็บนั้นผ่านช่องทางที่ปลอดภัย
   (ตัวจัดการรหัสผ่านขององค์กร หรือส่งมือต่อมือ) — ไม่ใช่ทางแชท ไม่ใช่ทางอีเมล
   ให้เขาเก็บเป็น `SUPPORT_HMAC_KEY` ที่เซิร์ฟเวอร์

4. **เปิด "enforce user identity validation" ทีหลังเท่านั้น**
   เปิดก็ต่อเมื่อยืนยันแล้วว่าเซิร์ฟเวอร์ของเขาเซ็น hash ได้ถูกต้องจริง
   ถ้าเปิดก่อน ผู้ใช้ทุกคนของเว็บนั้นจะใช้แชทไม่ได้ทันที

5. **ส่งสคริปต์ให้ทีมนั้น**
   ก็อปจากหน้าโครงการได้เลย มีปุ่มคัดลอกอยู่ในแถวของโครงการนั้น

6. **ทดสอบด้วยหน้าเดโม**
   เปิด `/kit/demo.html` (ตั้ง `data-project` เป็นรหัสที่ต้องการทดสอบ)
   ดูว่าปุ่มขึ้นและ `onReady` ทำงาน

7. **ตั้ง webhook (ไม่บังคับ)**
   ระบบดึงข้อมูลเองทุก 10 วินาทีอยู่แล้ว webhook แค่ทำให้ข้อความเข้ามาไวขึ้น
   วิธีตั้งอยู่ในกล่องแก้ไขโครงการ หัวข้อ "ຕັ້ງຄ່າ webhook ໃນ Chatwoot"

## 7. เวอร์ชันและความเข้ากันได้

เส้นทาง `/kit/v1/` คือสัญญาที่เราให้ไว้กับทุกเว็บที่ติดตั้งไปแล้ว

- **ภายใน `v1` ไม่มีการเปลี่ยนแปลงที่ทำให้ของเดิมพัง** ชื่อแอตทริบิวต์ `data-*`
  และคำสั่งใน `window.AIDCSupport` จะไม่ถูกลบหรือเปลี่ยนความหมาย
- **ถ้าจำเป็นต้องเปลี่ยนจนของเดิมพัง จะออกเป็น `/kit/v2/` แทน** และ `/kit/v1/`
  จะยังอยู่ต่อไปพร้อมรับการแก้บั๊ก ทีมที่ยังไม่พร้อมย้ายจึงไม่ต้องรีบทำอะไร
- ไฟล์ถูกแคชไว้ 5 นาที การแก้บั๊กใน `v1` จึงถึงทุกเว็บภายในเวลาไม่นาน
  โดยที่ทีมคุณไม่ต้องแก้อะไรเลย
- อ่านเวอร์ชันที่กำลังใช้อยู่ได้จาก `AIDCSupport.version` — แนบค่านี้มาด้วยเวลาแจ้งปัญหา
