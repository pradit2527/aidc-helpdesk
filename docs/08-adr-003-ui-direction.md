## 1. การตัดสินใจ

> ### ใช้ **แนวทาง B** — พาเลตต์เชิงความหมายตาม `21-ui-ux-design.md` §4

| มิติ | ค่าที่ล็อก |
|---|---|
| สีแบรนด์ | `--primary: #1D4ED8` · hover `#1E40AF` · subtle `#EFF6FF` · focus ring `#2563EB` |
| พื้นผิว | หน้า `#F8FAFC` · การ์ด `#FFFFFF` · หัวตาราง `#F1F5F9` |
| ตัวอักษร | `#0F172A` / `#475569` / `#64748B` · ขอบ input `#64748B` (ต้องผ่าน 3:1) |
| ฟอนต์ | **Noto Sans Thai** (variable, self-host `.woff2`) ตัวเดียวทั้งระบบ |
| มุม | `4px` badge · **`8px` ค่าเริ่มต้น** (ปุ่ม/input/การ์ด) · `12px` dialog |
| ความเร่งด่วน / สถานะ / SLA | **15 คู่สีตาม §4.2–4.5** ที่วัด contrast จริงแล้วทุกคู่ |
| โหมดมืด | **ไม่ทำในเฟส 1** — ประกาศเป็น CSS variable ไว้แล้ว เพิ่มภายหลังได้โดยไม่แตะ component |

### เหตุผลที่เลือก

1. **พาเลตต์ผ่าน WCAG AA ครบ 15 คู่แล้ว** — วัดด้วยสูตร relative luminance จริง ไม่ใช่ประเมินด้วยสายตา ถ้าเลือกแนวทาง A ต้องสร้างพาเลตต์เชิงความหมายขึ้นใหม่ทั้งชุดแล้วตรวจซ้ำ (~3–4 วัน)
2. **ตรงกับ PDF ที่ระบบสร้างอยู่แล้ว** — `12-…` §7.3 กำหนดติดตั้ง Sarabun/Noto Sans Thai ใน image ของ WeasyPrint รายงานบนจอกับในไฟล์ PDF จึงหน้าตาตรงกันโดยไม่ต้องทำอะไรเพิ่ม
3. **สถานะ 7 ค่าที่ต้องแยกออกจากกันจริง** — ระบบมีสถานะครบ 7 ค่าตาม state machine การให้แต่ละค่ามีคู่สีของตัวเองทำให้ผู้ใช้ที่ไม่ได้ใช้ระบบทุกวันแยกออกได้ทันที
4. **ผู้ใช้ส่วนใหญ่เป็นผู้แจ้ง ไม่ใช่ power user** — พนักงาน 3,000 คนเปิดระบบเดือนละไม่กี่ครั้ง ระยะหายใจและปุ่มขนาด 44–48 px สำคัญกว่าความหนาแน่นของข้อมูล

## 2. สิ่งที่ยกมาจาก prototype (เก็บไว้ทั้งหมด)

รายการเหล่านี้เป็น**เทคนิคที่ยกข้ามพาเลตต์ได้** ไม่ผูกกับสีแดงของ prototype และหลายข้อเป็น
**ข้อกำหนดที่ต้องมีอยู่แล้ว** ไม่ใช่รสนิยม

| # | สิ่งที่ยกมา | เหตุผล |
|---|---|---|
| C-01 | **โหมดสำรองเมื่อสไตล์ชีตโหลดไม่สำเร็จ** — ยุบเป็นคอลัมน์เดียว ทุกอย่างยังอ่านออกและกดได้ พร้อมแบนเนอร์ภาษาไทย | เน็ตที่ไซต์งานหลุดจริง · `21-…` ยังไม่มีข้อนี้ |
| C-02 | **ตารางกลายเป็นการ์ดบนมือถือ** ห้าม scroll แนวนอนกับข้อมูลหลัก | กฎ M-3 ของ `21-…` §6.2 อยู่แล้ว — prototype ทำถูก ให้ทำตาม |
| C-03 | **มาตรวัดความเร่งด่วนแบบขีดไล่ความสูง** วางคู่กับป้ายสี P1–P4 | ทำให้อ่านลำดับได้ทั้งจากสีและจากรูปทรง — เสริมกฎ "ห้ามสื่อด้วยสีอย่างเดียว" ของ §5 ให้แน่นขึ้น |
| C-04 | **แถบซ้ายไล่ความหนา 4/3/2/1 px ตามระดับ** และ **เส้นขอบประสำหรับ `cancelled`** | มีอยู่ใน `21-…` §5.2 อยู่แล้ว — ย้ำว่าเป็นข้อบังคับ ไม่ใช่ทางเลือก |
| C-05 | `--tap: 44px` บังคับทั้งระบบ + `@media (pointer:coarse)` ขยายปุ่มเล็กอัตโนมัติ | มือที่ใส่ถุงมือหรือเปื้อนที่ไซต์งาน |
| C-06 | `env(safe-area-inset-bottom)` ในแถบล่าง / bottom sheet / toast | มือถือจอบาก |
| C-07 | `font-variant-numeric: tabular-nums` ทุกที่ที่ตัวเลขเรียงเป็นคอลัมน์ | ตัวเลข SLA และรายงานต้องตรงคอลัมน์ |
| C-08 | สถาปัตยกรรม token 2 ชั้น (ramp → บทบาท) | ทำให้เพิ่มโหมดมืดในเฟส 2 ได้โดยไม่แตะ component |

## 5. สิ่งที่ ADR นี้ **ไม่ได้** ตัดสิน

- ผังหน้าจอและ user flow — ยังใช้ `21-ui-ux-design.md` §1–3 ตามเดิม
- ฟังก์ชันและโมเดลข้อมูล — อยู่ที่ `05-…` และ `06-…`
- คำถามใน `21-…` §9 (UX-01…UX-06) ที่ยังรอ PM: ผู้แจ้งเห็นตัวเลข SLA หรือไม่ · ใช้ พ.ศ. หรือ ค.ศ. · ถ้อยคำ "(เวลาทำการ)"
