## 1. ภาพรวมระบบ

### 1.1 วัตถุประสงค์

สร้าง web application รับแจ้งปัญหาและติดตามงาน support ของกลุ่มบริษัท AIDC 7 บริษัท ทดแทนการแจ้งผ่าน LINE/โทรศัพท์/อีเมลที่กระจัดกระจาย เพื่อให้ (1) ไม่มีเรื่องแจ้งตกหล่น (2) วัด SLA ตาม AIDC-IT-SLA-001 ได้จริง (3) ปฏิบัติตาม SOP-01…SOP-10 อย่างตรวจสอบย้อนหลังได้ (4) มีคลังความรู้ให้ผู้ใช้แก้ปัญหาเบื้องต้นเอง

### 1.2 ขอบเขต (In scope — MVP เฟส 1)

| กลุ่มความสามารถ | สาระสำคัญ |
|---|---|
| Ticket + SLA + Assign | แจ้งปัญหา · แยกประเภทงาน · จัดระดับอัตโนมัติ · มอบหมาย · ติดตามสถานะ · นับ SLA 2 โหมดนาฬิกา |
| Multi-company + สิทธิ์ | แยกข้อมูล 7 บริษัท · RBAC 53 permission · row-level scoping |
| **Escalation** | Tier 1/2/3 + ยกระดับสู่ผู้บริหาร ตามกฎที่ตั้งค่าได้ |
| **คำขอบริการ + การอนุมัติ** | Service catalog พร้อมเป้าหมายเวลารายรายการ + อนุมัติแบบเรียงลำดับ |
| **Checklist** | Onboarding / Offboarding บังคับครบก่อนปิดงาน |
| **Problem + RCA** | ติดตามสาเหตุราก · วัด Repeat Incident |
| **ทะเบียนระบบงาน + Uptime** | บันทึกเหตุขัดข้อง (ด้วยมือ) เพื่อคำนวณความพร้อมใช้งาน |
| Dashboard + รายงาน | KPI-1…KPI-7 ตามเอกสารควบคุม · export Excel/PDF |
| Knowledge Base + แจ้งเตือน | คลังบทความ · แจ้งเตือนในระบบ/อีเมล/ช่องทาง chat |

### 1.3 นอกขอบเขต (Out of scope เฟส 1)

Asset/Inventory Management เต็มรูปแบบ · Change Management + CAB (SOP-08) · ปฏิทินบำรุงรักษาและงานตามกำหนดการซ้ำ (SOP-09) · การเฝ้าระวัง Backup Job และ Restore Test (SOP-07 ข้อ 1/2/6) · ทะเบียน License และการจัดซื้อ · Status Page แยกโฮสต์ · การเชื่อมระบบ Monitoring อัตโนมัติ · Access Review รอบ 6 เดือนอัตโนมัติ · KPI Self-Service Deflection · Chat แบบ realtime · Mobile native app · SSO จริง (ออกแบบเผื่อแล้ว) · Auto-classify ด้วย AI · Customer portal สำหรับลูกค้าภายนอก

> เหตุผลรายข้อดู `06-sop-workflow-mapping.md` §5 (N-01…N-10)

## 2. บทบาทผู้ใช้

| รหัส role | ชื่อไทย | ขอบเขตข้อมูล |
|---|---|---|
| `end_user` | ผู้แจ้ง | ticket ที่ตนสร้างหรือถูกระบุเป็นผู้ร้องขอ |
| `agent` | เจ้าหน้าที่ support | ticket ในบริษัทที่ตนถูกมอบหมาย |
| `company_admin` | ผู้ดูแลระดับบริษัท | ทุก ticket ในบริษัทของตน |
| `manager_viewer` | ผู้บริหาร (อ่านอย่างเดียว) | ตามบริษัทที่ได้รับสิทธิ์ |
| `super_admin` | ผู้ดูแลระบบส่วนกลาง | ทุกบริษัท |

> **ตำแหน่งในองค์กร** (Head of IT, CEO, DPO, Incident Commander, Tier 2/3 group) **ไม่ใช่ role** — ผูกคนกับตำแหน่งผ่านตาราง `escalation_contact` (`02-data-model.md` §5.3)
> **ผู้อนุมัติ** ไม่ต้องมี role พิเศษ — สิทธิ์ `approval.decide` ให้ที่ระดับแถว `approval_request.approver_id`

### US-01 แจ้งปัญหาจากมือถือหน้างาน `end_user` · MVP **(แก้)**

| AC | เกณฑ์ |
|---|---|
| AC-1 | **Given** ล็อกอินบนมือถือ **When** กรอกหัวข้อ+รายละเอียด เลือกหมวดหมู่ **ตอบว่าปัญหากระทบใครบ้างและเร่งด่วนแค่ไหน** แล้วกดส่ง **Then** ระบบสร้าง ticket สถานะ `new` **คำนวณระดับความสำคัญให้เอง** และแสดงเลขที่ ticket |
| **AC-2** | **Given** อยู่หน้าแจ้งเรื่อง **When** เลือกผลกระทบ "ทั้งแผนก" และความเร่งด่วน "เร่งด่วนมาก" **Then** ระบบแสดงว่าเป็น **P2 – สูง** พร้อมเป้าหมายเวลา และแสดงว่าเจ้าหน้าที่ทบทวนระดับนี้ได้อีกครั้ง |
| **AC-3** | **Given** ผู้แจ้งส่ง `priority` มาโดยตรงผ่าน API **When** เรียก `POST /tickets` **Then** ระบบตอบ `422` — ระดับความสำคัญไม่ใช่ค่าที่ผู้ใช้กรอก |
| AC-4 | **Given** แนบรูป 8 MB **Then** ระบบบีบอัดฝั่ง client ให้ ≤ 2 MB ก่อนอัปโหลด และแสดง progress |
| AC-5 | **Given** กรอกไม่ครบ **Then** แสดงข้อความภาษาไทยชี้ฟิลด์ที่ขาด และ**ไม่**ล้างข้อมูลที่กรอกไว้ |

### US-05 หยุดนับ SLA ระหว่างรอ `agent` · MVP **(แก้)**

| AC | เกณฑ์ |
|---|---|
| AC-1 | **Given** ticket `in_progress` **When** agent เปลี่ยนเป็น "รอผู้แจ้ง" **Then** **ระบบบังคับให้เลือกเหตุผล 3 แบบ** และนาฬิกา SLA หยุด |
| **AC-2** | **Given** เลือกเหตุผล "รออะไหล่/ผู้ให้บริการภายนอก" **When** ยังไม่มีคอมเมนต์สาธารณะแจ้งผู้แจ้ง **Then** ระบบ**ไม่ยอมให้เข้าสถานะนี้** — ต้องแจ้งผู้รับบริการก่อนจึงหยุดนับเวลาได้ |
| AC-3 | **Given** อยู่ "รอผู้แจ้ง" **When** ผู้แจ้งคอมเมนต์กลับ **Then** สถานะกลับเป็น `in_progress` อัตโนมัติและเลื่อนกำหนดเวลาออกไปเท่าที่หยุด |
| **AC-4** | **Given** ผู้แจ้งไม่ตอบ **When** ครบ 1 วันทำการ **Then** ระบบส่งติดตามครั้งที่ 1 · ครบอีก 1 วันทำการส่งครั้งที่ 2 · **ยังไม่ตอบภายใน 3 วันทำการหลังครั้งที่ 2 จึงปิดเป็น `closed`** พร้อมแจ้งว่าเปิดใหม่ได้ |

### US-11 ตั้งค่า SLA และเวลาทำการ `super_admin` · MVP **(แก้)**

### US-17 ทบทวนระดับความสำคัญ `agent` / `end_user` · MVP **(แก้)**

| AC | เกณฑ์ |
|---|---|
| AC-1 | **Given** ticket ระดับ `P3` **When** agent ปรับเป็น `P1` พร้อมเหตุผล **Then** ระบบคำนวณกำหนดเวลาใหม่**จากเวลาที่ปรับ** ไม่ใช่จากเวลาสร้าง · ตั้งเป็นเหตุขัดข้องร้ายแรง · แจ้ง Head of IT และทีม On-call ทันที |
